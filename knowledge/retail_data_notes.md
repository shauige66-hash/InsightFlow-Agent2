# 零售数据口径说明（德国站 / 法国站 2011）

本文件是分析时必须遵守的口径，不是建议。数据本身没有清洗，下列事实会直接改变结论，
不做处理就会得出错误答案。

## 1. 期间不完整

- 数据截止 **2011-12-09**，12 月只有 9 天。
- 因此**任何以 12 月为终点的月度环比都不成立**；需要环比时，用 10 月对 11 月这类
  两个完整月份。
- 报告里提到月份时，必须说明该月是否为完整月份。

## 2. 这些编码不是商品

`stock_code` 里混有会计与费用科目，不能当作商品参与排名：

| 编码 | 含义 |
|---|---|
| `M` | 手工调整（Manual） |
| `POST` | 运费（Postage） |
| `DOT` | 运费（Dotcom postage） |
| `C2` | 运费 |
| `BANK CHARGES` | 银行手续费 |
| `PADS` | 填充物 |
| `CRUK` | 慈善捐赠 |
| `D` | 折扣 |

计算商品维度的销售额、退货额、退货率时，必须先排除这些编码。

## 3. 金额与退货的口径

- 行金额 = `quantity * unit_price`。
- `is_return = 1`（等价于 `quantity < 0`）表示退货行，其 `quantity` 为负。
- **GMV 默认指正向销售额**，即排除退货行；若报告的是"净销售额"，必须显式写明。
- 退货率按金额计算：`退货金额绝对值 / 正向销售额`。

## 4. 缺失与异常

- `customer_id` 有 66 行为空；按客户维度分析时要说明这部分被排除。
- 存在 2 行零或负单价；这类行不参与金额计算，但要在数据质量小节里报出来。
- 同一发票内可能重复出现同一 `stock_code`（64 组），汇总金额时按行累加，不做去重。

## 5. 结论表述要求

- 每个结论后面注明口径（是否含退货、是否排除非商品编码、月份是否完整）。
- 数据不足以支撑的问题（例如广告效果、库存、物流成本）直接说明不支持，不要推测。
